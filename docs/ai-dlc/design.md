# 설계와 결정 기록

## ADR-001 · 기존 Android 통합 포크

**선택:** melonDS Android 2.0.1 + 고정된 네이티브 하위 모듈을 재사용한다. 새로운 Android 프런트엔드/JNI를 처음부터 만들지 않는다.

**이유:** 듀얼 화면, 터치, 가상 키, 소리, 회전, 일시정지, 저장 파일, 상태 저장, ROM 검색이 이미 통합되어 있다. 새 코어 통합은 생명주기·오디오·버퍼·저장 위험을 늘린다. 한국어 설정 안내와 안전성 개선에 변경을 집중한다.

**경계:** 상류 Kotlin namespace `me.magnum.melonds`와 JNI 이름은 불필요한 위험을 피하기 위해 유지하고, 외부 Android application ID만 `io.github.seoulds.emulator`로 분리한다. 이는 이름만 바꾼 런처가 아니라 코어를 포함해 빌드하는 독립 앱이다.

## ADR-002 · 얇은 한국어 안내 계층

첫 실행과 메뉴에서 접근할 수 있는 설정/도움말 화면을 추가하고, 원작 설정 저장소를 읽어 구성 현황을 표시한다. 문서 URI를 일반 파일 경로처럼 해석하지 않으며, 파일 선택·권한 부여는 기존 SAF 경로로 연결한다. 첫 실행 완료 상태와 실제 ROM 폴더 상태는 분리한다. 안내를 닫았다고 ROM이 준비되었다고 간주하지 않는다.

취소·뒤로 가기·Activity 재생성·설정에서 복귀·빠른 중복 터치가 중요한 테스트 경계다. 표시한 상태는 해당 시점의 설정 점검이며 저장 폴더의 미래 쓰기 성공을 보증하지 않는다.

## ADR-003 · DS 직접 부팅과 권리 경계

기본 콘솔은 DS, 원작 `use_custom_bios=false` 및 `show_bios=false`를 유지한다. DS 직접 부팅용 FreeBIOS/생성 펌웨어는 원작 구현이다. 독점 BIOS/펌웨어를 앱에 추가하지 않는다. 사용자가 원본 펌웨어 메뉴나 DSi 모드를 선택하는 경우 필요한 파일의 권리를 확보해야 하며, 별도 사용법·검증이 필요하다.

## ADR-004 · 저장과 생명주기

게임 내부 저장(SRAM 파일)과 에뮬레이터 상태 저장(slot/quick save)은 서로 다르다. 원작의 저장 경로 선택과 네이티브 저장 로직을 유지하고 한국어 안내에서 차이를 명확히 한다. 비동기 저장 작업의 중복 실행·중단 경계를 점검한다. 구체적인 동시성 설계·테스트는 [저장 안전성](../save-safety-ko.md)에 기록하며 최종 Git diff와 변경 기록이 기준이다.

프로세스 강제 종료·권한 회수·저장 공간 부족에서 완전한 원자적 저장을 가정하지 않는다. 백업은 사용자 지정 저장 폴더에서 별도로 수행해야 한다. 새 application ID는 원작 앱의 private storage에 접근할 수 없으므로 자동 이전을 약속하지 않는다.

## ADR-005 · 성능 기본값

S24 대상 산출물은 ARM64로 빌드하되 원작의 다른 ABI 빌드 가능성을 제거하지 않는다. 기기별 벤치마크 없이 고해상도·프레임 제한 해제·백그라운드 최적화 예외를 강제하지 않는다. 원작 기본 렌더링/해상도/JIT 설정을 기준선으로 시작한다. FPS는 게임의 논리 속도·프레임 페이싱·음질과 함께 관찰해야 한다.

## ADR-006 · 배포와 공급망

원작 자동 nightly tag 강제 push, 자동 Play Store 업로드, 원작 서명키 설정 흐름을 CI에서 제거한다. 새 CI는 `contents: read`, 재귀 checkout, 명시적 Java, 정적 검사와 약관 동의가 있는 Android 빌드만 수행한다. APK와 소스는 자동으로 외부 스토어에 게시하지 않는다.

`upstream-lock.json`은 소스 기준선이며 Gradle Wrapper와 빌드 도구 버전도 검사한다. `package_source.py`는 깨끗하고 커밋된 tree만 수집하고 하위 모듈 파일·라이선스·manifest를 포함한다. GitHub 자동 소스 ZIP만으로는 하위 모듈이 빠지므로 완전한 대응 소스로 안내하지 않는다.

## 데이터 흐름

```text
사용자 로컬 ROM 폴더 → Android SAF URI 권한 → 원작 ROM 검색/목록
        → 기존 EmulatorActivity → JNI → 고정된 melonDS 코어
        → 듀얼 화면/오디오/입력 + 원작 저장 경로

한국어 안내 → 설정 저장소에서 구성 읽기 → 상태/설명 → 기존 설정 진입
하네스 → 정적/단위/Lint/빌드 결과 → 실행별 JSON·로그·APK 해시
```

새 안내 화면은 게임 파일이나 URI를 서버로 전송하지 않는다. 원작의 선택적 온라인 기능은 [개인정보 안내](../privacy-ko.md)에 별도로 기재한다.

## ADR-007 · Android PCAP 배포 의존성 분리

원작에 포함된 LBL 광고 조항 헤더의 라이선스 결합 불확실성을 발견해, Android에서 사용하지 않는 PCAP 백엔드를 빌드 어댑터로 제외한다. `app/cmake/SeoulAndroidDependencies.cmake`는 예상한 소스/포함문이 정확히 하나인지 확인한 뒤 `Net_PCap.cpp`를 제거하고 필요한 Android 플랫폼 소스를 빌드 디렉터리에 생성한다. 상류 하위 모듈/핀을 바꾸지 않으며 원본 파일과 고지를 대응 소스에 보존한다.

구성 성공만으로 링크 성공을 주장하지 않는다. 최종 ARM64 네이티브 링크와 실제 헤더 의존성·심볼 확인은 통과했고 [재현 명령과 해시](../testing/native-pcap-audit.md)를 기록했다. APK 패키징/서명 검증은 별도 게이트다. 이 변경은 DS 로컬 실행과 Slirp 경로를 보존하기 위한 범위 제한이며, 직접 PCAP 네트워크 기능을 제공한다고 약속하지 않는다.

## ADR-008 · 내부 versionCode 마이그레이션 연속성

표시 버전은 `0.1.0-alpha01`로 시작하지만 Android `versionCode`는 상류 기준선40을 유지한다. 원작 `Migrator`가 versionCode를 데이터 마이그레이션 순서로 사용하므로 1로 되돌리면 초기화/향후 구형 마이그레이션 재실행 의미가 달라질 수 있다. 독립 application ID 덕분에 상류 앱 설치와 충돌하지 않으며, 후속 포크는 41 이상으로 증가시킨다. 표시 버전과 내부 마이그레이션 카운터를 혼동하지 않는다.

## ADR-009 · 개인 사용용 네이티브 최적화와 증거 결합

Android Debug 서명/설치 ID는 유지하되 `-PseoulDsOptimizeNative=true`로 네이티브 CMake만 RelWithDebInfo를 선택한다. 배포 키나 flavor를 새로 만들지 않는다. 주 추천 산출물은 최적화 APK 하나이며 비최적화 Debug는 개발 백업으로만 둔다.

검증은 플래그 존재가 아니라 실제 cache·유효 최적화 옵션·Ninja 완료 상태를 읽고, APK에 들어간 core/JNI ELF의 GNU build ID를 해당 그래프의 실제 ELF와 비교한다. PCAP 의존성/심볼 부재도 다시 확인한다. 컴파일 DB의400개 구성 항목은 실제 빌드된 타깃/객체 수와 다르므로 혼용하지 않는다. 저장 가드 호스트 테스트는 항상 켜진 CHECK로 바꾸어 -O0와 -O2/-DNDEBUG 각각 동일한5개 사례를 실행한다. 이 증거는 빌드 출처·구성 검증이지 S24 성능 측정이 아니다.
