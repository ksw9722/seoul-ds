# 요구사항과 수용 기준

## 목표와 범위

Galaxy S24에서 사용자가 적법하게 보유한 DS 게임 덤프 또는 직접 작성한 홈브루를 실행할 수 있는 Android 앱을 만든다. 초기 목표는 **검증 가능한 독립 포크 MVP**이며, 특정 게임의 완벽한 호환성·무손실 저장·Play Store 승인을 약속하지 않는다. 사용자는 `nda`라고 표현했지만 파일 형식을 자동 변환하거나 비공식 포맷으로 취급하지 않고 일반적인 `.nds` DS 파일을 안내한다.

| ID | 요구사항 | 수용 기준 | 증거 |
|---|---|---|---|
| R01 | 동작하는 원작 통합 기반 | Android 2.0.1 및 재귀 하위 모듈의 정확한 커밋 고정 | lock 파일·하네스 pin 검사 |
| R02 | 독립 앱 정체성 | 설치 ID가 원작과 다르고 앱 이름/아이콘에서 원작 공식 앱으로 오인시키지 않음 | Gradle·리소스 정적 검사, APK manifest 확인 |
| R03 | 한국어 시작 경험 | 처음 실행, 뒤로 가기, 회전/재생성, 메뉴 재진입 경로 제공 | 단위/정적 검사 + 기기 체크리스트 |
| R04 | 로컬 ROM 권한 | Android 문서 선택기 사용, 취소 시 손상 없음, 권한 해제 후 복구 안내 | 원작 경로 보존, 기기 테스트 |
| R05 | 듀얼 화면·터치·입력·소리 | 원작 렌더/입력/오디오 구현 보존, S24에서 테스트 후에만 실기기 통과 | 변경 범위 리뷰·수동 테스트 |
| R06 | 저장 데이터 보호 | 게임 내부 저장/상태 저장 차이 안내, 반복 저장/중단/복귀 위험 검토 | 코드 리뷰·단위 테스트·저장 재실행 테스트 |
| R07 | 현대 Android 빌드 | SDK36/min24, Java21, NDK28, CMake3.22.1, ARM64 APK 생성 | Gradle 빌드·패키지 검사 |
| R08 | 재현 가능한 하네스 | 단일 명령이 실행별 로그·시간·커밋·정확한 실패/차단 상태 기록 | 하네스 자체 테스트·report.json |
| R09 | 권리·보안 경계 | 상용 ROM/독점 BIOS/게임 이미지/비밀키를 배포하지 않음 | 경로·바이트 패턴 검사 + 사람 리뷰 |
| R10 | GPL 공개 배포 준비 | 원작 고지와 변경 표시, 정확한 대응 소스·하위 모듈 제공 | 소스 묶음 manifest·해시·배포 점검 |
| R11 | 과장 없는 결과 | 정적/단위/빌드/실기기/게임 호환성 결과를 별도 표시 | 검증 행렬·릴리스 노트 |

## 비목표

새 에뮬레이터 코어 개발, 게임 다운로드·복제 방지 우회, DSi 설정 자동 구성, 멀티플레이 보장, 클라우드 저장/계정 서비스, 성능 수치 조작, 원작 앱 데이터 자동 마이그레이션, 무승인 기기 설치, 스토어 등록·유료화는 MVP 범위가 아니다.

## 주요 위험

1. 저장 중 프로세스 종료, 저장 경로 권한 만료, 클라우드 문서 공급자의 지연/오류.
2. S24 모델별 SoC·Android·GPU 드라이버 차이와 발열로 인한 성능 변동.
3. 상태 저장의 코어 버전 간 비호환 및 앱 삭제 시 앱 전용 저장소 유실.
4. 원작 이미지/자동업데이트/배포 워크플로가 새 포크 정체성을 잘못 가리키는 문제.
5. 로컬 빌드 성공을 실기기 또는 상용 게임 검증으로 오해할 위험.

위험 대응은 [설계](design.md)와 [실기기 검증표](../testing/s24-device-checklist.md)에 연결한다.
